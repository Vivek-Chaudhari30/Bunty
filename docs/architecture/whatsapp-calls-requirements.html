Everything WhatsApp and calling need

I researched three things: what Meta and the phone companies require in India, what Vellum's code actually does, and what our router and plugins still lack. Short version: the code side is about 3 to 4 weeks of focused work. The bigger risks are not code. Meta's new AI policy, Indian phone numbers, and company registration decide whether real users can be on WhatsApp and Indian numbers at all.

Show-stoppers: decide these before building

S1 Meta's WhatsApp terms ban "general-purpose AI assistants"

Section 4.7 "AI Providers" of the Meta Terms for WhatsApp Business Platform (checked today, last modified 23 Sep 2026) bars businesses whose primary function is offering AI or general-purpose assistants from using the platform. Meta decides who that covers. It applied to new businesses from 15 Oct 2025 and to everyone from 15 Jan 2026. Meta says it targets AI model providers, not businesses using AI for customer service. Bunty is an AI assistant reached over WhatsApp, so it sits close to the line. Italy and the EU forced exemptions. Nothing similar exists for India.

Risk: the WhatsApp number or business account gets banned. Options: describe and build Bunty on WhatsApp as a task service (reminders, bookings, calls made for you) rather than open chat; ask a Meta partner manager or a Business Solution Provider for a ruling; keep phone calls as the channel that can't be switched off. Calls aren't affected by this policy.

S2 Twilio can't give us an Indian phone number

Twilio sells no Indian local or mobile numbers. Its only Indian number type is toll-free, and that only receives calls. Its India rules say outbound calls to India must use a non-Indian caller ID. Indian phones now label those calls "International Call", and spoofed Indian caller IDs are blocked. Users calling a US number pay international rates (about ₹2/min with an ISD pack, more without).

Meaning: Twilio works for a team-only prototype. Real users need an Indian provider: Exotel (real-time audio streaming, Mumbai region, audio format close to Twilio's) or Plivo (India data region). That means a new channel adapter, because Vellum only speaks Twilio.

S3 Both of those need a registered Indian company

Exotel and Plivo KYC need GST or a Certificate of Incorporation plus PAN. Meta business verification needs GST, a Certificate of Incorporation or PAN, with the legal name matching exactly. Without verification we're capped at 2 numbers and 250 business-started conversations a day. That's fine for a prototype, but not for launch.

S4 Bunty can't WhatsApp a clinic or shop first

Meta's messaging policy only allows messaging people who gave their number and opted in to us. A clinic that never opted in to Bunty isn't an allowed recipient, even with an approved template. Outside the 24-hour reply window only templates can be sent at all. So reach_contact should call non-users, and use WhatsApp only for people who messaged us in the last 24 hours.

Setup for each assistant

Run from an operator shell, not by the assistant itself (Vellum refuses credentials set from the agent's own shell). Values come from K1 to K7. The Meta, Twilio, Deepgram and ElevenLabs values are the same on every assistant.

assistant credentials set --service anthropic  --field api_key              <key>
assistant credentials set --service whatsapp   --field phone_number_id      <id>
assistant credentials set --service whatsapp   --field access_token         <system user token>
assistant credentials set --service whatsapp   --field app_secret           <app secret>
assistant credentials set --service whatsapp   --field webhook_verify_token <token>
assistant credentials set --service twilio     --field auth_token           <token>
assistant config set twilio.accountSid   <AC...>
assistant config set twilio.phoneNumber  <+1 shared number>
assistant credentials set --service deepgram   --field api_key <key>
assistant credentials set --service elevenlabs --field api_key <key>
assistant config set ingress.enabled true
assistant config set ingress.publicBaseUrl https://chintu.example.com
assistant config set services.stt.language multi
assistant config set calls.disclosure.enabled true
assistant channel-verification-sessions create --channel whatsapp   # owner sends the code from WhatsApp
# owner on phone: verify with an outbound code call to +91 00000 00001
  • Also: in Meta, point the app's webhook at the router /whatsapp and subscribe to messages; set the app to Live mode. In Twilio, point the number's voice URL at the router /twilio/voice (only after V2, or an assistant will overwrite it).
  • Set each owner's voices in services.tts.providers.elevenlabs.languageVoices (BUN-27). Set the phone admission floor to strangers if non-users should be able to call back.
  • Do not set VELAY_BASE_URL on our server; leave Vellum's managed tunnel off.
